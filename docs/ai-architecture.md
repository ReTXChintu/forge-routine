# AI Architecture

## Provider independence

OpenAI is the only provider ForgeRoutine ships with, chosen deliberately. It is still placed
behind an interface (§27, §45.12) because prompts, agents, and the domain must not be
rewritten if that ever changes, and because a deterministic fake is required for tests.

```
packages/ai/
├── provider/
│   ├── ai-provider.port.ts     the interface the application depends on
│   ├── openai/                 the real adapter
│   └── testing/                deterministic fake (tests only, never shipped)
├── agents/
│   ├── tutor/                  Socratic hints, concept explanation
│   ├── evaluator/              code evaluation after execution
│   ├── interviewer/            adaptive question + follow-up generation
│   ├── debugger/               broken-code authoring + diagnosis grading
│   ├── curriculum/             technology -> concept graph generation
│   ├── reviewer/               code review
│   └── planner/                daily routine composition
└── contracts/                  Zod schemas for every structured output
```

The `testing` provider is a hand-written fake with canned, schema-valid responses. It is not
a second AI vendor; it exists so §32's "structured-output validation" and "prompt regression"
tests can run offline and deterministically in CI.

## The port

```ts
interface AIProvider {
  generate(req: GenerateRequest): Promise<GenerateResult>;
  stream(req: GenerateRequest): AsyncIterable<StreamChunk>;
  structured<T>(req: StructuredRequest<T>): Promise<StructuredResult<T>>;
  embed(req: EmbedRequest): Promise<EmbedResult>;
}
```

`structured<T>` takes a Zod schema, derives a JSON schema, requests strict JSON mode, parses,
and validates. It never returns unvalidated data. On validation failure it retries once with
the validation error fed back as a correction turn, then throws `AIContractViolation`.

## Agents

An agent is **a prompt template + an output contract + a policy**, not a class hierarchy.
Each agent exports:

```ts
export const evaluatorAgent = {
  name: 'evaluator',
  model: 'reasoning',              // resolved to a concrete model by config
  contract: CodeEvaluationSchema,  // Zod
  buildPrompt(input): PromptSpec,
};
```

Model choice is symbolic (`fast` | `reasoning`) and resolved from environment config, so
model upgrades are a config change rather than a code change.

## Structured output is mandatory (§28, §45.7)

Business logic never parses prose. Every agent that feeds a decision returns typed JSON:

```json
{
  "score": 78,
  "strengths": ["Correct sliding-window logic"],
  "weaknesses": ["No cleanup of expired entries"],
  "conceptGaps": ["memory-management"],
  "recommendedDifficulty": "medium",
  "nextAction": "practice"
}
```

Free-form prose is allowed in exactly one place: text rendered directly to the user
(explanations, hints, interviewer turns). Even there the _envelope_ is structured, so we can
attach metadata and never guess where the message ends.

## Degradation

The product must remain usable when AI is unavailable. Each agent declares a fallback:

| Agent       | Fallback when AI fails                                  |
| ----------- | ------------------------------------------------------- |
| evaluator   | Test results only; quality dimensions marked `unscored` |
| tutor       | Static per-concept hints stored with the exercise       |
| planner     | Deterministic rule-based routine from the skill model   |
| curriculum  | Generation is queued and retried; no partial writes     |
| interviewer | Interview cannot start; the user is told plainly        |

An unscored dimension is never silently written as a low score — that would corrupt the skill
model, which is the product's long-term memory.

## Cost, budget, and observability

Every call passes through one instrumented client that records latency, prompt/completion
tokens, model, agent name, user, and outcome into `AIInteraction`. `AI_DAILY_TOKEN_BUDGET`
caps per-user daily spend; exceeding it degrades to the fallbacks above rather than erroring.

Prompts are versioned (`promptVersion` on every `AIInteraction`) so an evaluation-quality
regression can be traced to the prompt change that caused it.

## Safety of AI-authored content

Curriculum and exercises generated by the model are data, not instructions. Generated content
is validated against its schema, length-bounded, and stored; it is never evaluated as code
and never interpolated into a system prompt without escaping.
